Google Play Level Up 計畫 — Play Games Rewards（Play Games 獎勵）領獎端到端流程

玩家在 Play Games 取得獎勵後，進入遊戲即可自動入帳。本頁說明 Android 如何串接 PGS v2（初始化、自動登入、取得 Auth Code、解鎖成就），以及獎勵如何發放到領獎中心。

概述

Play Games Rewards 的獎勵來自 Play Games，不是遊戲商城內購。玩家進入 App 後，Client 需查詢尚未消耗的購買，交由 Server 發放到領獎中心，成功後再向 Google 消耗該筆紀錄。

這條流程能運作，前提是 Android App 已串接 Play Games Services v2：初始化 SDK、優先靜默登入、取得 Auth Code 供 Server 綁定帳號，並在對應時機解鎖成就。完成綁定後，再查詢是否有未領取的 Rewards。

Google 要求在啟動 App與回到前景時各查詢一次。進入領獎中心前會再查詢一次，確保畫面刷新時獎勵已入帳。

入帳成功後不另跳提示。玩家至領獎中心領取，流程與既有補單相同。

背景與目標

這是 Google Play Level Up 計畫的要求：遊戲需支援 Play Games Rewards。

平台既有補單流程，用於商城付款後尚未入帳的購買。Play Games 獎勵並非遊戲內下單，商品編號也不同；若沿用同一條補單，Server 會視為一般內購，導致發獎錯誤或失敗。

因此 Rewards 需獨立處理：查詢 Google → 請 Server 發獎至領獎中心 → 成功後再消耗該筆購買。

查詢與分流寫在大廳／商店流程，不寫入金流 plugin。後續更新金流套件時，Rewards 邏輯不會被覆蓋。

與 AI 的協作方式

規格不是一次貼完就結束。較有效的做法是先對齊架構，再分段實作，最後以問答收斂行為。

  1. 對齊架構：Rewards 與商城補單分流；金流 plugin 只負責查詢 Google，不負責發獎。
  2. 接上端到端：查詢未消耗購買 → Server 發放至領獎中心 → 成功後消耗。進入領獎中心前先完成發獎再刷新畫面。
  3. 若舊檔覆蓋導致無關功能被刪除（例如大富翁、條件式任務），請 AI 比對 git，只還原被誤刪的內容，不回退 Rewards。
  4. 行為不明確時，直接確認時機與條件。下列問題都已反映到實際邏輯。

實際提問並調整過的行為

成就領獎時，是否要向 Google 消耗該筆購買？
不需要。消耗發生在 Server 確認發獎成功之後。玩家之後在成就頁領獎，不會再次消耗。
裝置未登入 Play 商店時，進 App 哪些時機會跳出 Play Games 登入？
僅在進入大廳時可能顯示。Loading 與金流初始化不會顯示。正式版未登入則每次進大廳都顯示；測試版同一個 App 生命週期只顯示一次。
登入回傳未開啟 Play Games 獎勵開關時，能否送出發獎請求？
不能。未開啟則不向 Server 請求發獎，也不向 Google 消耗，避免舊環境被誤發。
測試版減少登入視窗後，是否仍能綁定 Play Games 帳號？
可以拆開。是否顯示登入視窗，與是否送出綁定無關。進大廳只要取得 Auth Code 就送綁定；Auth Code 為空則不送，送出也會失敗。
官方 Unity Plugin 能否直接使用？
目前工程無法滿足該 Plugin 所需的 Gradle 8。因此以 AndroidJavaObject 橋接 Play Games Android SDK，涵蓋 initialize、isAuthenticated、signIn、requestServerSideAccess、unlock。

PGS v2 串接

獎勵要自動入帳，App 必須先串接 Play Games Services v2。官方 Unity Plugin 需要 Gradle 8，與現有工程不相容，因此以 AndroidJavaObject 呼叫 Android SDK，封裝於 PgsNativeBridge。

進入大廳後依序處理下列四項：

1初始化 SDK

首次進入大廳建立 PgsManager，於 Awake 呼叫 PlayGamesSdk.initialize。僅在 Android 真機執行，Editor 會略過。

2自動登入

先呼叫 isAuthenticated。若已登入 Play Games，不顯示登入視窗；未登入則依正式／測試版規則決定是否呼叫 signIn()。

3取得 Auth Code

以 Web Client ID 呼叫 requestServerSideAccess。取得有效值後才送出 VALIDATE_PGS_ID，由 Server 將 Play Games 帳號綁定至遊戲帳號。空值不送。

4解鎖成就

進入大廳時解鎖「第一次登入遊戲」。遊戲內完成 FB／Line／Apple 等帳號綁定後，再解鎖「帳號綁定」。已解鎖的成就會記錄在本機，避免重複送出。

進入大廳時的處理

GameLobbyState 進入大廳時呼叫 PgsManager.OnEnterGameLobby()。登入視窗與綁定封包分開執行：

  1. 解鎖「第一次登入遊戲」成就
  2. 依規則決定是否顯示 Play Games 登入視窗
  3. 靜默取得 Auth Code；取得後送出綁定封包

初始化

進入大廳時呼叫 PgsManager.EnsureExist()。物件建立後立即初始化 SDK，並以 DontDestroyOnLoad 保留至整個 App 生命週期。Google 的 callback 位於 Android 執行緒，需先排回 Unity 主執行緒，再更新狀態或送出封包。

自動登入

PGS v2 優先使用靜默登入：

  • 已登入 Play Games：isAuthenticated 為 true，不顯示登入視窗
  • 未登入：才可能顯示系統登入畫面（signIn）
  • Loading 與金流初始化不會顯示登入視窗，僅在進入大廳時判斷
  • 玩家於視窗完成登入後，若綁定尚未送出，會再取得一次 Auth Code

正式版與測試版的顯示次數規則見下一節。

取得 Auth Code

Auth Code 供 Server 向 Google 交換 Play Games 帳號，不會呈現給玩家。

  1. Client 以 Play Console 的 OAuth Web Client ID 呼叫 requestServerSideAccess
  2. Google 回傳 auth_code
  3. 字串為空時視為未登入，不送出綁定封包
  4. 有值則送出 VALIDATE_PGS_ID。登入回傳未開啟成就系統時也不送出，以相容舊包
  5. 同一 App 生命週期綁定成功後會記錄狀態，無須每次進入大廳都送出；需更新證明時再強制重取
規格不另外接入 Google Sign-In SDK。以 Play Games v2 的 requestServerSideAccess 即可完成成就系統綁定。

解鎖成就

Play Console 目前有兩個一次性成就，無需累積次數：

成就 解鎖時機 觸發方式
第一次登入遊戲 進入大廳 已接線：OnEnterGameLobby
遊戲內帳號綁定 FB／Line／Apple／IGS 等綁定成功 已提供 NotifyAccountBindingSuccess，待綁定流程呼叫
  • 實際呼叫 Google 的 API 為 AchievementsClient.unlock(成就 ID)
  • 已解鎖的成就以本機紀錄避免重複送出
  • 另預留累積用的 increment，以及開啟 Play Games 成就列表；目前兩個成就皆不需累積
  • 遊戲內成就頁領獎時不會再向 Google unlock。遊戲內成就對應的 google_play_id 改由 Server 處理

領獎流程

從查詢到入帳分為四步：

1查詢尚未消耗的購買

啟動遊戲、回到前景，或進入領獎中心前，各查詢一次。

2辨識 Play Games 獎勵後走獨立發獎

商品編號以 pg_reward 開頭，或為 jgp_160_01，視為 Rewards。其餘未消耗購買仍走既有商城補單。

3由 Server 發放至領獎中心

Server 成功後，獎勵出現在領獎中心。此步失敗則不向 Google 消耗，下次仍可查到同一筆。

4成功後才消耗該筆購買

消耗後 Google 不會再次回傳同一筆。失敗則保留，待下次查詢再發放，避免尚未入帳就被消耗。

查詢時機

  1. 金流初始化成功（進入遊戲時）
  2. App 從背景回到前景
  3. 開啟領獎中心前（先完成發獎，再刷新可領內容）

功能開關

每次登入先關閉「可發送 Play Games 獎勵」。登入回傳含 play_games_reward_system 且為 true 時才開啟。未開啟則視為該環境尚未上線此功能。

登入視窗與綁定

進入大廳時，登入視窗與綁定封包分開處理：

  • 登入視窗：引導玩家登入 Play Games。正式版未登入則每次進入大廳都顯示；測試版同一個 App 生命週期只顯示一次，重新啟動後才再顯示。
  • 綁定帳號：將 Play Games 帳號綁定至成就系統。不依是否顯示視窗決定——取得 Auth Code 即送出；為空則不送。
情況 是否顯示登入視窗 是否送出綁定
正式版，尚未登入 Play Games 每次進入大廳都顯示 取得 Auth Code 才送出
測試版，尚未登入 同一個 App 生命週期最多一次 取得 Auth Code 才送出
已靜默登入成功 不顯示 照常送出
未登入 Play Games 時，Google 無法核發 Auth Code。此時送出綁定必定失敗，因此空值直接略過。

問題與決策

  • 舊檔覆蓋誤刪無關程式：接入 Rewards 時，大廳內不相干的功能曾被一併覆蓋（大富翁、條件式任務、iPad 轉屏）。之後比對 git，只還原誤刪內容，保留 Rewards。
  • 入帳成功仍跳出日文提示：文案寫死日文，也不符合「至領獎中心領取」的體驗，因此移除。
  • 減少登入視窗時連綁定一併停送：測試版為降低打擾，一度連成就綁定都不送。之後改為視窗規則獨立，綁定仍會嘗試。
  • 舊環境尚未開啟功能：Server 未開啟開關即視為功能關閉，不對舊包送出發獎請求。
  • 官方 Unity Plugin 與 Gradle 不相容：PGS v2 Unity Plugin 需要 Gradle 8，本專案改以 AndroidJavaObject 呼叫 Android SDK。
  • Google callback 不在 Unity 執行緒：需先排回主執行緒，才能送出封包或更新狀態。

異動檔案

Android 以自訂橋接串接 PGS v2：初始化 → 優先靜默登入 → 取得 Auth Code 完成綁定 → 解鎖成就。Rewards 走獨立發獎，成功後才向 Google 消耗。

檔案說明
PgsNativeBridge.cs呼叫 Android SDK：初始化、查詢登入狀態、顯示登入、取得 Auth Code、解鎖／累積成就
PgsManager.cs進入大廳的入口：登入視窗規則、送出綁定、解鎖成就
PgsConfig.csWeb Client ID、Rewards 商品編號、成就 ID
PgsAchievementTracker.cs各成就的解鎖時機
HttpValidatePgsId.cs將 Auth Code 送至 Server，綁定 Play Games 帳號
GameLobbyState.cs進入大廳時啟動上述流程
ArkStore.cs查詢未消耗購買，並分流 Rewards 與一般補單
PgsRewardManager.cs請 Server 發獎；成功後消耗；讀取功能開關
HttpVerifyPgsReward.cs向 Server 請求發放該筆 Rewards
HttpSGCLogin.cs登入時讀取 Play Games 獎勵開關
AwardCenterState.cs開啟領獎中心前先完成發獎再刷新
GameManager.cs回到前景時再次查詢未消耗購買
